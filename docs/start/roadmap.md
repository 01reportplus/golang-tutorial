# 学习路线与练习方法

## 先确定学习目标

Go 的语法数量有限，可靠程序的难点却在边界：数据是否共享、错误由谁处理、goroutine 何时退出、网络什么时候超时、升级是否改变行为。建议用“能解释一个机制并写出边界测试”作为进度，而不是看完了多少页。

零基础读者先补充终端、目录、文本文件、二进制与十进制、基本 Git 操作。已有编程经验的读者可以快读安装与控制流，但不要跳过切片、接口、错误和并发。它们最容易被其他语言经验误导。

## 四条阅读路径

| 路径 | 阅读顺序 | 实验 |
| --- | --- | --- |
| 从零开始 | 01—17 → 24—28 → 39 → 18—23 | 改写每个完整程序；用测试证明理解 |
| 后端开发 | 语言 → 并发 → HTTP/SQL → 工程 → 40 | 为 API 加入持久化、超时和请求日志 |
| 已会 Go，补原理 | 11—17 → 23 → 31—32 → 35—38 | 对照编译器输出、race 和 profile |
| 面试与复习 | 规范索引 → FAQ → 练习答案 → 原章节 | 先口头预测，再运行反例 |

## 可执行的八周安排

第一周完成安装、语法、类型和函数，写一个输入校验程序。第二周学习字符串、切片、map、结构体和接口，完成文本统计 CLI。第三周学习错误、泛型与模块，给 CLI 加测试。第四周集中学习并发，每个实验都写出退出条件。第五周学习 I/O、JSON、时间和 HTTP，用 `httptest` 写客户端与服务端测试。第六周学习 SQL、配置、日志和安全，把 API 接到自选数据库。第七周做性能分析、构建和 CI。第八周阅读进阶专题，挑一个真实瓶颈做实验报告。

这不是必须遵守的时限。若只能零散学习，每次选择一个“可以验证的结论”，例如“append 是否会影响原切片”，比连续浏览多个新概念更容易形成理解。

## 每章怎样学

1. 先看目标，写出你现在的猜测。
2. 手动运行例子，记录输出、错误和版本。
3. 改变零值、空输入、超时、重复调用或并发数量。
4. 运行测试，解释为什么通过；必要时故意破坏实现，确认测试真的会失败。
5. 对照官方文档，把语言保证与当前实现区分开。

练习答案提供思路和关键代码，不是唯一实现。涉及架构与分布式系统的题目应说明约束，不能只给一个固定“最佳方案”。

## 仓库地图

`docs/` 是教程正文，`examples/basics/` 是语言语义测试，`examples/` 还包含最小程序和并发流水线。`cmd/wordcount/` 与 `cmd/taskapi/` 是命令入口；`internal/` 放项目实现和测试；`scripts/` 检查文档、完整代码块和生成站点；`.github/workflows/` 管理质量检查与 Pages 部署。

先运行 `go test ./...`，再运行项目。修改文章后执行 `python scripts/check_docs.py` 与 `python -m mkdocs build --strict`，避免让链接和正文逐渐脱节。

## 自测标准

读完基础后，你应能说明数组与切片的区别、接口为何可能不等于 nil、为什么 Go 没有隐式数值转换。读完并发后，你应能指出每个共享变量的保护机制、每个 channel 的关闭者和每个 goroutine 的退出路径。读完工程部分后，你应能展示测试、性能证据、构建命令和回滚办法。

练习：列出你最想完成的一个 Go 程序，分别写下输入、输出、失败方式和可测试边界；在学完本教程后重新评估最初的设计。

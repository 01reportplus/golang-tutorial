# 01 · 认识 Go：语言、工具链与适用场景

## 本章目标

理解 Go 解决哪些问题，区分语言、标准库、工具链和第三方生态，建立后续学习所需的基本模型。

## Go 程序怎样变成可执行文件

Go 源文件属于包。编译器检查语法和类型，把各个包编译后交给链接器生成可执行文件。可执行文件通常包含 Go runtime，负责 goroutine 调度、栈管理和垃圾回收，因此目标机器通常无需单独安装 Go。但使用 cgo、动态库或操作系统资源的程序仍可能有外部依赖，“Go 程序一定完全静态链接”并不成立。

`main` 包中的 `main` 函数是普通可执行程序入口。库包提供函数和类型供其他包导入。目录、包和 module 有不同职责：目录组织文件，包是编译与封装单位，module 是发布和依赖版本单位。

## 四个重要特征

Go 是静态类型语言，变量类型在编译期间确定；类型推断省略的是声明文字，不会把它变成动态类型。Go 的垃圾回收能回收不可达内存，但不会自动关闭文件、取消请求或结束 goroutine。Go 用接口表达行为，用结构体嵌入组合能力。Go 在语言中提供 goroutine、channel 和 select，标准库再提供锁、原子操作与 context。

这些机制降低了某些工程成本，也带来明确约束：循环依赖不允许；未使用的局部变量和导入会报错；错误通常显式返回；代码格式由 `gofmt` 统一。限制帮助团队减少风格选择，但仍需设计合理的模块边界。

## 和熟悉的语言比较

| 概念 | Go 的做法 | 容易误解的地方 |
| --- | --- | --- |
| 类与继承 | 结构体、方法、组合 | 嵌入不等于子类型继承 |
| 多态 | 隐式实现接口 | 类型不写 `implements` |
| 异常 | 返回 `error`；严重错误可 panic | 不应把所有失败都 panic |
| 线程 | goroutine 由 runtime 调度 | goroutine 不是没有成本 |
| 泛型 | 类型参数与约束 | 先有具体需求，再抽象公共操作 |
| 资源回收 | 显式 Close，常用 defer | GC 不负责外部资源的及时释放 |

## 怎样判断是否适合

Go 常用于网络服务、CLI、基础设施和数据处理。选语言还应考虑团队经验、目标平台、延迟要求和依赖生态。需要严格可预测的暂停时间、极小裸机环境或特定 GUI 框架时，应实际评估 runtime、二进制体积和库支持。不存在脱离工作负载的性能排名。

在服务开发中，很多性能问题来自慢查询、无界队列、连接泄漏和过多分配。先把 I/O、并发和错误边界设计清楚，再考虑更底层优化。

## 官方资料怎样使用

入门文档教用法，语言规范定义规则，包文档说明 API 契约，发布说明说明版本变化。运行时源码描述某个版本的实现，不能代替语言保证。读旧书时，遇到 GOPATH 开发方式、没有泛型、旧循环变量行为或老式 HTTP 路由，应查[版本差异](../appendix/versions.md)。

练习：解释“有 GC，所以不会内存泄漏”为什么错误；找一个始终被全局 map 引用的数据作为例子。

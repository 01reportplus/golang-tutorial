# 15 · 结构体、方法、嵌入与封装

## 用结构体表达有关联的数据

结构体将字段组合成一个值。推荐对公开或较长结构体使用带字段名的字面量，减少字段顺序变化引起的脆弱性。未导出字段只能由定义它的包直接访问。

```go
type Account struct {
    ID      int64  `json:"id"`
    Name    string `json:"name"`
    balance int64
}

func (a *Account) Deposit(cents int64) error {
    if cents <= 0 { return errors.New("金额必须大于零") }
    a.balance += cents // 真实业务还需检查溢出和并发
    return nil
}
```

字段 tag 是字符串元数据，JSON 等包按约定解释，编译器不会据此自动验证字段。不要认为 `validate:"required"` 写上之后，标准库就会执行校验。

## 值接收者和指针接收者

值接收者复制值，适合小型、不可变或有值语义的类型。指针接收者允许修改原对象，也避免复制大型或含锁的结构体。对同一类型的方法，尽量保持一致、清晰的接收者选择。

编译器在某些可寻址值的方法调用中自动取地址，但接口实现依据方法集，而不是调用时能否自动转换。T 的方法集与 `*T` 的方法集不同，这是接口章节的重要基础。

nil 指针可以作为方法接收者传入，方法能否处理取决于实现；一旦解引用仍会 panic。不要仅因“能调用”就认为 nil 总是合法对象。

## 方法值和方法表达式

```go
// a 为 *Account
deposit := a.Deposit // 方法值，绑定接收者
method := (*Account).Deposit // 方法表达式，接收者变成显式首参数
_ = deposit
_ = method
```

方法值会在创建时绑定接收者值。对指针接收者来说，后续对象修改仍可能被观察到；对值接收者，绑定的是副本。理解这一点有助于排查回调与延迟执行代码。

## 嵌入是组合

```go
type Logger interface { Printf(string, ...any) }
type Service struct {
    Logger
    Name string
}
```

嵌入字段可以提升其字段和方法的选择器，但不建立传统继承关系。两个嵌入字段具有同名成员时可能产生歧义，需要显式限定。给嵌入类型增加方法还可能改变外部类型的接口实现，公共 API 应谨慎依赖大范围方法提升。

推荐在能力确实属于外部类型时嵌入；仅仅为了少写 `s.logger.Printf`，未必值得扩大 API。命名字段往往能让依赖关系更明确。

## 构造与不变量

Go 没有强制构造函数机制，常以 `NewX` 命名。构造函数负责验证必要配置、初始化 map 或注入依赖；如果零值足够好用，就不必强制构造。跨包未导出字段能帮助维护不变量，但同包内部仍需遵守规则。

结构体相等要求所有字段可比较，tag 参与类型相关规则，却不是业务相等函数。比较时间、浮点或含切片的领域对象时，应设计显式比较逻辑。

练习：为库存类型实现增加和扣减方法，禁止负库存；分别使用值接收者和指针接收者，解释调用后对象的变化。再为含 Mutex 的类型说明复制风险。

# 07 · 常量、iota 与运算符

## 常量不只是只读变量

常量在编译期求值，可以没有具体类型。无类型常量参与表达式时，根据上下文确定类型，只要值可表示，就能适配多种类型。变量一旦获得静态类型，后续赋值不能任意改变它。

```go
const limit = 100
var a int8 = limit
var b int64 = limit
const third = 1.0 / 3.0
```

Go 常量支持比普通机器数值更精确的编译期运算，但赋给具体类型时仍受表示范围和精度限制。`const x = time.Now()` 不成立，因为函数调用不是这里需要的常量表达式。

## 用 iota 定义有序值

```go
type State uint8

const (
    StatePending State = iota
    StateRunning
    StateDone
)

type Permission uint8
const (
    Read Permission = 1 << iota
    Write
    Execute
)
```

`iota` 在每个 const 声明组中从 0 开始，每个 ConstSpec 增加一次。省略表达式会重复上一条表达式。不要在已对外持久化的枚举中随意插入成员，否则后面的数值可能改变；协议与数据库枚举往往更适合显式赋值。

Go 没有自动禁止无效枚举值。外部传入 `State(99)` 仍能构造，需要校验函数。也没有内置完整枚举遍历和名称映射，必要时写 `String` 方法或使用代码生成。

## 运算符优先级

从高到低主要是：乘除余数、移位与按位与；加减与按位或/异或；比较；逻辑与；逻辑或。复杂表达式请加括号表达意图，不要依赖读者背优先级。

`&&`、`||` 会短路；`&`、`|` 是位运算，不是替代写法。`++`、`--` 是语句，不能放进赋值表达式；Go 没有三元运算符，用 if 表达分支更清楚。

```go
allowed := Read | Write
canWrite := allowed&Write != 0
allowed &^= Write // 清除写权限位
```

`&^` 表示按位清除。位标志适合多个独立开关；互斥的业务状态通常使用枚举，避免制造无意义的组合。

## 除法、移位与求值

两个整数相除产生整数结果，`5/2` 为 2；需要浮点除法，先把至少一个操作数转换为浮点类型。运行时整数除以零会 panic。余数的符号与被除数有关，不能直接假定负数取模总能得到非负数组索引。

移位数量必须合法，负的运行时移位数会 panic。对位字段先明确无符号类型与位宽，避免符号扩展或中间表达式推断造成意外。

函数调用、通信以及部分表达式的求值有规范顺序，但不要写同时依赖共享副作用和复杂求值次序的表达式。把状态修改拆成独立语句通常更容易审查。

## 内置函数与版本

`len`、`cap` 查询大小，`make` 创建切片/map/channel，`new` 创建指针，`append` 和 `copy` 操作切片，`delete` 删除 map key，`clear` 清空 map 或把切片元素置零。`min`、`max` 与 `clear` 从 Go 1.21 加入。Go 1.26 扩展了 `new` 的用法，见指针章节。

练习：用位运算实现权限添加、检查与删除；说明为什么存入数据库的状态码不宜依赖可以任意调整顺序的 iota。

# 11 · 指针、值传递与内存所有权

## 所有参数都按值传递

指针保存变量地址，`&x` 取地址，`*p` 读取或写入指向值。指针本身也是值，将指针传入函数复制的是地址，不是被指向对象。Go 没有普通指针算术，空指针解引用会 panic。

```go
package main

import "fmt"

func addValue(n int) { n++ }
func addPointer(n *int) { (*n)++ }

func main() {
    n := 10
    addValue(n)
    fmt.Println(n) // 10
    addPointer(&n)
    fmt.Println(n) // 11
}
```

说“map、切片是引用传递”容易隐藏实际行为。切片复制的是包含底层数组关联、长度与容量的描述信息；map 值复制后关联同一个 map。函数内替换整个切片或 map 变量，通常不会替换调用者的变量，但修改共享内容会被观察到。

## new、make 与字面量

`new(T)` 分配一个取零值的 T 并返回 `*T`。`make` 专门初始化切片、map 或 channel，返回这些类型本身。`&User{Name: "Ada"}` 用结构体字面量直接构造指针，通常更可读。

Go 1.26 中，`new` 还可以接受确定类型的表达式并返回指向其值的指针，例如 `new(42)`。这需要 Go 1.26 语言版本；兼容更早版本时仍可先声明变量再取地址。不要对切片或 map 使用 new 后误以为内容已初始化：`new(map[string]int)` 得到的是指向 nil map 的指针。

## 返回局部变量地址是安全的

```go
func NewCount() *int {
    n := 1
    return &n
}
```

Go 保证变量在仍可访问时有效。编译器根据逃逸分析决定存储位置，并可能随版本和优化上下文改变。不要根据“写了 new”判断一定堆分配，也不要认为所有值传递都比指针慢。指针会增加间接访问、共享和 GC 扫描成本。

## 浅拷贝与深拷贝

复制一个结构体会复制其字段。如果字段是切片、map 或指针，复制后仍可能共享底层数据。深拷贝需要按语义逐层复制，并考虑循环引用、不可拷贝资源和并发时机。JSON 序列化往返通常不是可靠的通用深拷贝方法，会丢失类型、未导出字段或特殊语义。

设计 API 时说明谁能修改数据、调用返回后能否保留数据、是否复用缓冲区。例如返回内部切片会把修改能力交给调用者；返回 `slices.Clone` 的副本可以隔离元素存储，但元素若含指针仍是浅层隔离。

## 不应复制的值

使用后的 Mutex、WaitGroup、Once 和许多含同步状态的类型不应复制。把它们放进结构体后，应避免值接收者、按值传参和 append 引起的无意复制。`go vet` 可以发现部分问题，但不能代替类型契约。

## 练习

写一个含 `[]string` 字段的结构体，复制后修改元素，观察原值变化。再实现一个隔离切片元素的 Clone。解释为什么给 map 参数重新赋值与给 map 增加 key 的效果不同。

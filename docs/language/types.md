# 06 · 类型系统、数值与转换

## 类型决定操作集合

变量有静态类型，值也有类型。类型决定可执行的运算、可调用的方法以及赋值规则。Go 不进行普通数值的隐式转换，`int32` 与 `int64` 相加需要显式转换，即使当前值都很小。

| 类型族 | 常用类型 | 需要注意 |
| --- | --- | --- |
| 有符号整数 | int8、int16、int32、int64、int | int 的宽度取决于目标平台 |
| 无符号整数 | uint8、uint16、uint32、uint64、uint、uintptr | uintptr 不是受 GC 跟踪的指针 |
| 浮点 | float32、float64 | 有精度、NaN、无穷大问题 |
| 复数 | complex64、complex128 | real、imag、complex |
| 布尔和文本 | bool、string | bool 不能直接当整数使用 |
| 别名 | byte、rune、any | 分别对应 uint8、int32、interface{} |

处理文件大小、时间戳、协议字段时，根据契约选择位宽。`int` 适合索引和长度；不应假定它在所有平台都是 64 位。需要精确小数的场景应选择经验证的十进制方案或整数最小单位，不能简单使用二进制浮点保存金额。

## 定义类型与类型别名

```go
type UserID int64
type OrderID int64
type RawID = int64
```

`UserID` 和 `OrderID` 是不同的定义类型，不能直接互相赋值，显式转换表示开发者接受这种变化。`RawID` 是同一类型的另一个名字。定义类型能承载方法并表达领域含义；别名适合兼容迁移。`type A B` 不会自动继承 B 的方法。

## 转换不是解析

```go
package main

import (
    "fmt"
    "strconv"
)

func main() {
    n, err := strconv.Atoi("42")
    if err != nil { panic(err) }
    fmt.Println(n, strconv.Itoa(n))
    fmt.Println(string(rune(65))) // A，不是 "65"
    fraction := 3.9
    fmt.Println(int(fraction))   // 3，运行时浮点值向零截断
}
```

从字符串解析数值用 `strconv`，从整数转换成 string 表示生成对应 Unicode 码点的文本，二者完全不同。缩小整数位宽可能截断位；将负数转换成无符号类型也可能得到很大的值。外部输入应先检查范围。

## 溢出与浮点边界

常量必须能由目标类型表示，否则编译失败。因此 `int(3.9)` 这样的非整数常量转换会被拒绝，而先用 float64 变量保存 3.9 再转换，会按规则截断。运行时无符号整数按模运算；有符号整数溢出有 Go 定义的结果，不会自动产生业务错误。业务中的余额、计数器、尺寸计算仍要显式检查溢出。

`0.1 + 0.2` 不能作为所有浮点相等判断的模板。对测量值可结合绝对与相对误差；对 NaN，`x == x` 也可能为 false。排序和 map key 涉及浮点时，要专门考虑 NaN 与正负零。

## 用检查避免整数溢出

对于只允许非负数的计数，可以在相加前根据上界判断，而不是相加后再比较是否变小。后一种技巧容易在改成有符号、混合类型或增加业务条件后失效。

```go
func AddCount(a, b uint64) (uint64, error) {
    if b > math.MaxUint64-a {
        return 0, errors.New("计数超出 uint64 范围")
    }
    return a+b, nil
}
```

业务还可能有更小的上限，比如一次最多导入一百万行。机器表示范围和业务范围要分别校验。处理 `size*count` 时也要先验证乘法是否溢出，再分配切片，不能把外部输入直接转换成长度。

## 默认类型与类型推断的边界

`x := 1` 通常得到 int，`x := 1.0` 得到 float64，`x := '中'` 得到 rune。给一个无类型常量提供上下文，例如 `var x int32 = 1`，则按上下文确定类型。类型推断不是“编译器猜业务需要”，它按语言规则选择静态类型。

具名类型能减少误用，但不会自动检查所有不变量。`type Port uint16` 仍可以构造 Port(0)，如果零不是合法业务值，应提供解析或验证函数，并明确零值如何处理。

## 可赋值与可比较

并非所有类型都支持 `==`。切片、map、函数只能与 nil 比较；数组元素均可比较时数组可比较，结构体所有字段可比较时结构体可比较。接口比较还取决于其中的动态值，装入切片后参与相等比较可能 panic。

需要比较切片内容用 `slices.Equal`；比较 map 内容可使用 `maps.Equal`，但值仍要满足相应条件。不要把“是否可比较”“是否相等”“业务上等价”当成同一个问题。

# Go 版本差异与升级策略

## 本教程基线

本仓库 `go.mod` 声明 Go 1.26，正文可执行源码使用这个基线。本机 Go 版本、实际执行的检查与远端 CI 结果见仓库 `VALIDATION.md`；配置了矩阵不代表每个版本已在本机运行。

核对日期为 2026-10-29。官方文档此时已列出 Go 1.27。本教程使用 1.26 方便与本机验证一致，并单独解释 1.27 变化。新读者安装时应从官方下载页选择仍受支持的补丁版本，更新前查发布说明。

这张表只列本教程相关变化，不是各版本完整发布说明。新 API、语言语义和 runtime 改变分别可能受工具链、go 指令或环境设置影响，应逐项核对。

## Go 1.26：new 表达式

```go
package main

import "fmt"

func main() {
    port := new(8080)
    fmt.Println(*port)
}
```

它适合需要指针表示可选字段的代码。支持该语法需要对应语言版本；使用新编译器但 module 仍声明较低版本时，不能假定所有新语法自动生效。已有 `new(T)` 仍表示创建零值变量。

1.26 还放宽泛型类型约束中的某些自引用限制，go fix 增加现代化更新能力。自动修改前应保存工作、看 diff 并运行测试，不要因为工具声称不改变行为就省略项目验证。

## Go 1.27：单独的迁移关注点

方法可以声明自己的类型参数，函数类型推断适用于更多赋值上下文，结构体字面量允许更广的字段选择器形式。接口方法仍不能声明类型参数，也不能由泛型方法实现接口方法。泛型方法不是让所有运行时多态自动变成泛型。

1.27 新增 encoding/json/v2 与 encoding/json/jsontext，v2 默认对非法 UTF-8 和重复对象名称等采用更严格处理。旧 encoding/json API 保持支持，但错误文字等细节可能变化。迁移应比较实际协议行为，不只替换 import。

这里不把 1.27 专属语法混入 Go 1.26 可执行示例；可在独立 module 或明确升级分支实践，并给兼容性增加测试。

## 升级清单

1. 阅读语言、标准库、工具链和平台相关发布说明。
2. 固定当前依赖与基线，运行现有测试并保存性能数据。
3. 升级工具链，先保持项目语言版本，观察构建和诊断。
4. 有意识地升级 go 指令，检查循环、计时器和新语法行为。
5. 检查生成代码、cgo、反射、unsafe 与依赖库的版本支持。
6. 执行 race、集成与协议兼容测试，比较延迟和内存。
7. 分阶段发布，并准备二进制与数据兼容的回滚方案。

支持策略与补丁下载见[发布历史](https://go.dev/doc/devel/release)、[工具链选择](https://go.dev/doc/toolchain)与[下载页](https://go.dev/dl/)。实际部署版本以当时官方发布为准。
